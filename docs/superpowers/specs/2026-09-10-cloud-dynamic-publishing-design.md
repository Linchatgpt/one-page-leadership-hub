# 雲端動態文章發布設計

日期：2026-09-10

## 目標

作者在工作台完成文章後，預覽與正式發布都使用精萃領導™學習中心的標準文章格式。除主圖由 Codex 另行製作外，文章內容、表格、工具卡、情境案例、自我整理、工作紀錄、行動承諾、口播音訊與外部影音都能由工作台發布後立即在線上顯示，不必為每篇內容重新部署。

## 範圍與不可變條件

- 移除目前 ARTICLE 19 的來源、生成頁、專屬主圖與摘要音檔，讓下一篇由工作台重新建立為 ARTICLE 19。
- ARTICLE 01–18 的來源檔與生成文章頁必須保持逐位元一致；實作前後以 SHA-256 驗證。
- 首頁可因移除 ARTICLE 19、加入動態文章卡與載入新腳本而改變。
- 不變更 ARTICLE 01–18 的標題、正文、圖片、音訊、互動資料、網址或版型。
- 作者工作台仍是獨立入口，公開目錄與文章頁不加入工作台連結。
- 工作台不負責生成主圖，也不顯示主圖路徑欄位。

## 採用方案

新增一套伺服器端 JavaScript 標準文章渲染器，供「預覽」與「正式動態文章」共用。既有 ARTICLE 01–18 繼續使用靜態 HTML；新文章從 ARTICLE 19 起使用雲端資料與動態標準模板。

不採用每次發布後觸發 Netlify 重建，因為這會增加等待時間、部署次數與 credits 消耗，也無法解決預覽模板與正式模板分岔的根本問題。

## 資料模型

工作台發布的文章資料必須包含：

- `id`、`title`、`subtitle`、`category`、`reading_minutes`、`summary`
- `start_prompt`、四項 `orientation`
- 三題 `quick_scan`，每題兩個選項與回饋
- `body_markdown`
- `case`
- 四題 `questions`，每題兩個選項
- `focus_tips`
- 零至兩個 `tools`
- 選填 `audio_script`、音訊資產與 `video_url`
- 選填 `hero_image`；沒有圖片時不輸出圖片區塊

發布前由後端驗證必要欄位與數量。資料不完整時回傳可讀的錯誤，不建立半成品正式文章。

## 編號與更新規則

- 靜態文章最高編號固定基準為 18。
- 新發布草稿的正式 ID 取「18、現有雲端正式文章最高編號」中的最大值加一。
- 第一篇新文章因此取得 `article_19`。
- 編輯已發布文章時沿用原本 `article_N`，不得建立新 ID 或重複目錄卡。
- 草稿 ID `draft_<timestamp>` 不得出現在公開網址或目錄。

## 共用渲染器

建立可測試的渲染模組，輸出與現有標準文章一致的結構與 CSS class：

1. 品牌列與回目錄連結
2. Hero、摘要、三階段學習節奏與開始前提問
3. `01 深入閱讀`、四項導讀、三題快問快答與 Markdown 正文
4. 正確渲染 Markdown 標題、段落、清單與表格
5. 依 `<!-- TOOL_N -->` 將工具卡放回相關段落，不集中於文末
6. `02 情境案例`
7. `03 自我整理`四題、缺題提示、整理結果與焦點建議
8. `04 工作紀錄`
9. `05 行動承諾`
10. 外部影音與完整頁尾

所有內容先做 HTML escaping，再由受控的 Markdown 轉換規則產生 HTML，避免把文章資料當成任意 HTML 執行。

## 預覽與正式發布流程

### 預覽

工作台將目前文章 JSON 傳給 `/api/render-preview`。該端點呼叫共用渲染器，回傳完整標準文章 HTML，並保留「回到文章工作台」入口。預覽不寫入正式文章資料。

### 發布

工作台將目前文章傳給 `/api/publish-article`。後端先驗證、配發或保留正式 ID，再將正規化資料寫入 Netlify Blobs。發布成功後：

- 首頁透過 `/api/list-published` 立即取得新文章卡。
- 新文章卡連至 `/article?id=article_19`。
- `/article` 讀取雲端文章並使用同一共用渲染器輸出正式頁。
- 修改已發布文章後重新整理即可看到更新，不需重新部署。

## 圖片與音訊

- 沒有 `hero_image` 時完全省略主圖 `<figure>`，不顯示空框、SVG 佔位圖或其他文章圖片。
- Codex 之後生成圖片，可將圖片存入雲端資產並更新該文章的 `hero_image`；文章重新整理後即可顯示。
- 摘要音訊獨立存入 Netlify Blobs，不把大型 base64 內容塞進文章清單回應。
- 文章資料只保存音訊資產網址或識別碼；首頁播放器直接讀取該音訊端點。
- 未生成音訊時不顯示「播放摘要」空播放器。

## 既有文章保護

- 建立 ARTICLE 01–18 來源檔與生成頁的 SHA-256 基準。
- 自動測試確認動態渲染器、發布 API 與首頁合併邏輯不寫入或改寫 ARTICLE 01–18。
- 建置後再次比較 SHA-256；若任何檔案不同，停止提交與部署。
- 雲端資料若與 `article_01` 至 `article_18` 同 ID，只能供既有明確允許的外部影音同步使用，不得覆蓋靜態文章卡與正文。

## 錯誤處理

- 缺少必要欄位：保持草稿，顯示具體缺少項目。
- AI 回傳不完整：不允許發布，原草稿不變。
- 雲端寫入失敗：不顯示發布成功，也不刪除草稿。
- 正式文章不存在：回傳品牌一致的 404 頁與回目錄連結。
- 表格或工具資料格式錯誤：阻止發布並指出欄位，不把 JSON 或 Markdown 符號直接顯示給讀者。

## 驗證

自動測試至少涵蓋：

- 下一篇配發 `article_19`，後續依序增加。
- 更新已發布文章不產生第二張卡。
- 預覽與正式文章使用同一渲染器。
- 標題、表格、工具位置、三題快問快答、四題自我整理、案例、頁尾均存在。
- 沒有圖片時不輸出主圖區；加入圖片後正確顯示。
- 有音訊才顯示播放器，且文章清單不包含大型 base64。
- ARTICLE 01–18 的來源與生成頁 SHA-256 全部不變。

瀏覽器驗證使用一篇測試草稿完成：AI 整理、預覽、保存、發布、目錄出現、開啟正式頁、修改後原網址即時更新。測試資料完成後從雲端刪除，不污染正式目錄。

## 發布與回復

- 所有修改只在 `codex/dynamic-publishing-template` 分支進行。
- ARTICLE 19 移除與動態發布架構分成獨立提交。
- 未經使用者明確要求，不合併 `main`、不推送 GitHub、不部署 Netlify。
- 若驗證結果不符合期待，放棄此分支即可回到目前 `main`；正式網站不受影響。
